# FoxForge v0.1.0-alpha.4.3

`v0.1.0-alpha.4.3` is the third Alpha 4 hotfix. It addresses a command-flow failure found during real Umbrel testing from iOS Safari over a plain HTTP LAN address.

## Fixed

- FoxForge no longer assumes that `crypto.randomUUID()` is available in every browser context.
- When a browser exposes Web Crypto random bytes but not `randomUUID()` (notably WebKit/Safari in some non-secure HTTP contexts), FoxForge installs an RFC 4122 UUIDv4 fallback backed by `crypto.getRandomValues()` before React renders.
- Native `crypto.randomUUID()` remains preferred and unchanged when available.
- If secure random generation itself is unavailable, FoxForge fails explicitly rather than silently generating weak command identities.

The fix covers all existing browser command flows that rely on UUID identities, including printer setup, queue operations, inventory mutations and common printer-control commands.

## Regression coverage

- Unit tests cover the native, fallback and fail-closed paths.
- Browser acceptance explicitly removes `Crypto.prototype.randomUUID` before application bootstrap and verifies that FoxForge restores compatible UUID generation.
- Existing responsive/browser, security, backend/frontend and container gates remain required before publication.

## Scope and compatibility

This hotfix does not change printer transports, persisted configuration schema, SQLite schema, vendor capabilities or dependencies. Existing `/data` remains compatible with Alpha 4.2.

The Alpha 4.2 package should not be used as the canonical physical acceptance candidate for direct HTTP/WebKit command workflows because the discovered browser failure can prevent commands from reaching the backend. Physical Umbrel/X2D/OpenKE validation should continue against the exact Alpha 4.3 package after its immutable image is published.

`AUD-003` and `AUD-013` remain validation-required until their physical evidence requirements are completed against the published package.
