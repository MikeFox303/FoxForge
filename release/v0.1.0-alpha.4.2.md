# FoxForge v0.1.0-alpha.4.2

Second hotfix for `alpha.4`, focused on completing interface stabilization before physical printer validation.

## Fixed

- Add Printer now renders in an isolated `document.body` modal layer instead of mixing with sticky/filter stacking contexts.
- Modal backdrop owns the viewport, dialog surfaces remain opaque, and global controls no longer render above the modal.
- Body scrolling is locked while Add Printer is open and restored when it closes; Escape closes the dialog.
- Phone modal geometry respects dynamic viewport and iOS safe-area constraints.
- Operator Access was moved into the responsive topbar flow and no longer covers workspace content.
- Mobile Operator Access hit-testing and stacking were corrected so route content cannot intercept its control.
- Phone, tablet, 16:9 and 32:9 layouts are bounded without uncontrolled horizontal stretching or clipping.
- Russian and Ukrainian locked-write/fallback errors are localized and covered by responsive checks.
- Invalid CSS custom-property usage found during stabilization was corrected.
- Backend request-local aiohttp state now uses typed `RequestKey` storage, removing the warning found during release-readiness validation.

## Regression protection

- Browser Acceptance covers Overview, Printers, Queue, Materials, Inventory, Farm and System.
- Required viewport projects are phone 390x844, tablet 900x1024, desktop 1920x1080 and ultrawide 5120x1440.
- Dedicated Add Printer coverage checks viewport ownership, z-order, opaque surface, scroll lock/recovery and Escape close behavior.
- Dedicated Operator Access coverage checks viewport containment, hit-testing, Add Printer separation and compact close state.
- RU/UK layout coverage is retained for phone and 16:9 desktop.
- Browser Acceptance fails on `pageerror` or `console.error` across primary routes.
- Frontend unit tests reject undefined CSS custom-property references unless an explicit fallback is present.
- The guarded release workflow reruns production-container Browser Acceptance against the exact release commit before creating the immutable Git tag or publishing the semantic GHCR image.

## Validation status

The stabilization PR passed Web UI, Python/printer contracts, deployment authentication, container, security and Browser Acceptance gates. Its final Browser Acceptance evidence contained 66 screenshots covering the supported viewport matrix, RU/UK layouts, Add Printer and Operator Access states and was manually reviewed before merge.

The release workflow must still revalidate the exact merged release commit before publication. Automated CI, mocks and browser emulation do **not** constitute physical printer validation.

## Physical validation handoff

After the immutable image digest is published and the Umbrel Store package is pinned to that digest, physical testing should use the exact Alpha 4.2 release on:

- Raspberry Pi 5 / Umbrel;
- Bambu Lab X2D + AMS 2 Pro;
- Moonraker/OpenKE / Ender 3 V3 KE.

`AUD-003` and `AUD-013` remain `VALIDATION REQUIRED` until that real-device evidence is collected.

## Upgrade notes

No persistence schema change is introduced by this UI hotfix. Back up `/data` before updating. The Umbrel package must be updated only after the guarded release workflow publishes and verifies the immutable multi-architecture image digest.
